# TITO 在真实 vLLM 多轮 rollout 中的端到端验证

日期：2026-10-29。数据：`results/<模型>/results.json`（Kaggle 2×T4，vLLM 0.32.0）。

## 设置

- **模型**：Qwen2.5-1.5B-Instruct、Qwen3-0.6B（关闭思考），revision 固定；服务端使用官方模板启动。
- **rollout**：每条轨迹从第一个助手轮次开始，最多 8 轮，每轮由模型采样（T=1.0，max_tokens=1024），观察沿用数据集。
- **TITO 驱动**：`/v1/completions` 直接传 token id；观察 token 由 `/tokenize` 在服务端渲染。
- **配对对照**：同一份采样再用 `/tokenize` 按官方模板和补丁 v2 重渲染，检查前缀是否成立；三条链路的事件分别交给 `build_samples(trajectory)`。
- **数据**：每个数据集选 seed 0 下前 100 条至少有 2 个助手轮次的轨迹。SWE-smith 是第一个运行的数据集，只分到软预算的 1/3，两个模型都在 64 条轨迹时停止（已发出的批次全部完成），其余两个数据集各 100 条。
- **资源**：会话 4,768 s，GPU 时间 79.57 min（预测约 80 min）。

## 结果：整条轨迹可完整合并的比例

| 模型 | 数据集 | 轨迹 | 轮次 | TITO | 重渲染 + 官方 | 重渲染 + v2 |
|---|---|---:|---:|---:|---:|---:|
| Qwen2.5-1.5B | SWE-smith | 64 | 481 | **64（100%）** | 20（31%） | 21（33%） |
| | Toucan | 100 | 218 | **100（100%）** | 88 | 91 |
| | nebius | 100 | 661 | **100（100%）** | 56 | 56 |
| | 合计 | 264 | 1,360 | **100%** | 62.1% | 63.6% |
| Qwen3-0.6B | SWE-smith | 64 | 501 | **64（100%）** | 0 | 37（58%） |
| | Toucan | 100 | 221 | **100（100%）** | 0 | 88 |
| | nebius | 100 | 760 | **100（100%）** | 0 | 79 |
| | 合计 | 264 | 1,482 | **100%** | 0% | 77.3% |

**训练 token 总量，相对 TITO**（训练行数更多，是因为每次合并失败都会断开成新的一行，每行重复携带完整历史）：

| 模型 | SWE-smith | Toucan | nebius |
|---|---|---|---|
| Qwen2.5：官方 / v2 | 1.81× / 1.80× | 1.09× / 1.08× | 1.60× / 1.60× |
| Qwen3：官方 / v2 | 5.02× / 1.74× | 1.61× / 1.07× | 5.00× / 1.30× |

**逐轮合并检查**（v2）：

- Qwen2.5：934 / 1,098 = 85.1% 前缀成立；失败中 retoken 154 次，template 10 次。
- Qwen3：1,083 / 1,220 = 88.8% 前缀成立；失败中 retoken 121 次，template 16 次。Qwen3 官方模板每次都失败（1,220 / 1,220）。

## 失败来源

- **retoken 全部来自模型自己的采样**：v2 下每一次 retoken 失败的分歧点都落在本轮采样的 response 内（Qwen2.5 154 / 154，Qwen3 121 / 121），对应模型采样出的非规范切分。
- **template 类**：v2 下剩余的少数 template 失败是工具调用 JSON 被重新格式化（如 `-74.0060` → `-74.006`）等输出改写。
- **TITO**：按构造对这两类都免疫。528 条轨迹全部可完整合并，每条恰好 1 个训练行。

## 其他观察

- **非规范切分有聚集**：在此前已出现过一次非规范切分的轨迹中，后续轮次再次出现的比例更高：

  | 模型 | 轨迹中尚未出现过 | 此前已出现过 |
  |---|---|---|
  | Qwen2.5 | 10.7% | 27.8% |
  | Qwen3 | 4.9% | 29.2% |

  这可能是因为某些轨迹的内容（如大段代码）本身更容易产生非规范切分，也可能是 TITO 把非规范 token 保留在上下文中所致。本实验无法区分两者，只作为观察记录。

- **多轮下 retoken 比例高于单轮实验**：例如 Qwen2.5 在 nebius 上，单轮实验为 7%，这里为 14%。原因同上，未定。
- **解析核对**：第一轮用相同 prompt 和种子分别走 completions 和 chat 接口，两次采样相同的有 475 次。其中 474 次客户端与 vLLM 的 Hermes 解析完全一致；1 次不一致（Qwen2.5，SWE-smith，客户端没有解析出工具调用），记录中没有保存文本，原因未查明。
- **停止 token**：没有出现正常结束却缺少停止 token 的情况；以 `<|endoftext|>` 结束的有 6 次，都是 Qwen2.5。

## 局限

- 观察是离策略的（来自数据集），本实验只研究 token 层面的一致性，不评价 agent 的能力。
- 重渲染链路评估的是“同一份采样交给那条链路会怎样”，并不是该链路真实运行时的结果。
- SWE-smith 只完成了 64 条轨迹。
- 每个配置只运行一次；只测了 0.6B 和 1.5B 两个模型，T4 上用 fp16。
- token 倍数是数据层面的统计；换算成训练时间需要用 P3-A 的关系（速度约为 token 比的 0.82 倍），属于估算。

## 补充运行：重渲染驱动的实测与非规范切分聚集（2026-10-29）

会话 8,743 s，GPU 时间 145.8 min（预测约 125 min）。判定规则在运行前固定。数据在 `results/supplement/`；分析脚本为 `results/supplement/analyze_supplement.py`，在仓库根目录运行即可复现本节的数字。

**运行情况**

- 两种驱动方式的冒烟测试全部通过。
- TITO 补跑 SWE-smith 第 64–99 条：
  - Qwen2.5 完成 36 条；
  - Qwen3 完成 35 条，另有 1 条因单个 HTTP 请求超过 30 分钟超时而失败。当时两个客户端共用服务端，负载较高；这条已排除并计数。
- 重渲染驱动：
  - Qwen2.5 的 3 个数据集各完成 100 条；
  - Qwen3 的 SWE-smith 再次因时间预算停在 64 条。重渲染驱动比预计慢，SWE-smith 单独就用了 6,787 s。
- 分析只使用两种驱动方式都完成的轨迹：Qwen2.5 300 条，Qwen3 264 条。

### 1. 非规范切分的聚集：由 TITO 上下文造成（判定规则 B）

每轮的非规范切分率，按“此前是否已出现过”分组：

| 模型 | 驱动 | 此前未出现 | 此前已出现 |
|---|---|---:|---:|
| Qwen2.5-1.5B | TITO | 139/1,212 = 11.5% | 105/408 = **25.7%** |
| | 重渲染 | 132/1,195 = 11.0% | 59/387 = 15.2% |
| Qwen3-0.6B | TITO | 58/1,194 = 4.9% | 84/288 = **29.2%** |
| | 重渲染 | 57/1,209 = 4.7% | 12/275 = 4.4% |

- **主指标**（“此前已出现”条件下，TITO 减重渲染；按轨迹 bootstrap 10,000 次，计算 95% 置信区间）：
  - Qwen2.5：**+10.5 个百分点 [+4.6, +16.6]**；
  - Qwen3：**+24.8 个百分点 [+14.5, +35.7]**。

  两个模型的置信区间都整体大于 0，按事先固定的判定规则**支持 B**：TITO 把模型自己的非规范 token 保留在上下文里，使后续采样更容易再次出现非规范切分。
- **对照**：“此前未出现”条件下，两种驱动方式的比率几乎相同。
  - 差值：Qwen2.5 +0.4 个百分点 [−1.3, +2.1]，Qwen3 +0.1 个百分点 [−0.5, +0.8]。
  - 说明两种驱动方式的基线一致，差异只在非规范 token 进入上下文之后才出现。
- **Qwen3 在重渲染驱动下完全没有聚集**（4.7% → 4.4%）。因此 Qwen3 的聚集可以全部归于 TITO 上下文。Qwen2.5 在重渲染驱动下仍有轻度聚集（11.0% → 15.2%），说明内容本身也有一部分作用。
- **第 1 轮之后的总体非规范切分率**：
  - Qwen2.5：TITO 225/1,320 = 17.0%，重渲染 172/1,282 = 13.4%；
  - Qwen3：TITO 110/1,218 = 9.0%，重渲染 38/1,220 = 3.1%。

**解读**：TITO 保证了训练与推理逐 token 一致，代价是模型会在上下文中看到并延续自己的非规范切分，采样分布因此改变。重渲染每轮都会把上下文规范化，没有这个效应，但会造成训练与推理不一致，以及合并失败。在 RL 训练中，这种自我强化是否会被学到、是否有害，本实验无法回答，只说明了它存在。

### 2. 重渲染链路的实测合并率：与推断值基本一致

在相同的轨迹上，用重渲染驱动实测的整条轨迹完整合并率，与全量运行中按配对推断的 v2 值对比：

| 模型 | 实测 | 推断 | 分数据集（实测 / 推断） |
|---|---:|---:|---|
| Qwen2.5 | 189/300 = **63.0%** | 183/300 = 61.0% | SWE-smith 45/36，Toucan 92/91，nebius 52/56 |
| Qwen3 | 204/264 = **77.3%** | 204/264 = 77.3% | SWE-smith 34/37，Toucan 90/88，nebius 80/79 |

- 合计上，推断值与实测值相差不超过 2 个百分点，说明全量运行中的配对推断是可靠的。分数据集看，两者最多相差 9 条轨迹（Qwen2.5 SWE-smith，45 / 36）。
- 实测的训练 token 总量是 TITO 的 1.36 倍（Qwen2.5）和 1.15 倍（Qwen3），低于推断的 1.62 倍和 1.46 倍。原因之一是重渲染驱动的轨迹采样本身不同（例如在不同的轮次未正常结束）。这个倍数只作为参考。
- TITO 在全部轨迹上完整合并：Qwen2.5 300/300，Qwen3 299/299。

### 3. 其他

- **`others_mismatch` 共 4 个轮次**：都是模型输出中的一部分在解析和重渲染时被丢弃或改写，例如工具调用没有闭合、文本中有残缺的 UTF-8 字节（`�`）。
- **全量运行中唯一的那次解析不一致，很可能就是这个原因**：它出在 `rustedpy…pr_121`。这条轨迹在本次运行中第一轮同样采样出了残缺的 UTF-8 字节。客户端解码与 vLLM 解析器对残缺字节的处理不同。

### 局限

- 两种驱动方式的采样在第一个分歧点之后不再配对，聚集分析比较的是两种驱动方式下的总体比率，属于观察性比较。
- 每个配置只运行一次；只测了 0.6B 和 1.5B 两个模型，T4 上用 fp16；观察是离策略的。
- Qwen3 的 SWE-smith 只有 64 条轨迹可以比较。
